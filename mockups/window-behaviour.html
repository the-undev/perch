Window behaviour

A Window page joins the settings rail, last, carrying the two facts about how the app lives on this machine: whether it stays in the tray, and whether it starts at login. Two rows, not cards; each row's sentence says what its state does, and the sentences change with each other.

Round of 3 November 2026 · drawn on the approved ink palette · for 0.2.0

The tray is config

[window] tray, default true. On: closing hides, the icon shows, rescans and quits. Off: no icon, closing quits. Only a deviation is written.

Login is the file

The toggle reads whether ~/.config/autostart/perch.desktop exists; Save writes or removes the entry itself. Nothing is stored twice.

Each start repoints the entry

The app knows its own image from APPIMAGE. When the entry exists, every start rewrites it to point at the running image, so updating is running the new version once.

Source runs hold the toggle

Run from source there is no image to point the entry at, so the login toggle is held and its row says why. The tray row stays editable.

The command line follows the tray

With the tray off, --hidden is ignored and a second launch always shows: nothing may start unreachable.

1 · The Window page, defaults

Tray on, start at login off: the state after 0.1.0, and Save writes nothing. The login row's sentence already says what turning it on will do, derived from the tray setting beside it.

How the window lives on this machine.

Stay in the tray

Closing the window hides it. The tray icon shows it, rescans and quits; clicking the icon toggles the window.

Start at login

perch starts when you log in, hidden in the tray.

~/.config/autostart/perch.desktop → ~/Applications/perch-0.2.0-x86_64.AppImage

Save writes every page's edits

What Save writes

No config: the autostart entry itself, Exec pointing at the running image with --hidden.

[Desktop Entry]
Type=Application
Name=perch
Exec=/home/owner/Applications/perch-0.2.0-x86_64.AppImage --hidden

Every later start rewrites the Exec line to the image then running.

3 · The tray, off

One edit, two sentences change: closing now quits, and the login row stops saying "hidden in the tray" because nothing may start unreachable. The autostart entry loses --hidden on the same Save.

How the window lives on this machine.

Stay in the tray

Off. No tray icon; closing the window quits perch.

Start at login

perch starts when you log in, with the window open.

~/.config/autostart/perch.desktop → ~/Applications/perch-0.2.0-x86_64.AppImage

Save writes every page's edits

What Save writes

[window]
tray = false

And the autostart entry again, now without --hidden: a login start with no tray opens the window.

4 · Run from source

Under pnpm dev there is no APPIMAGE, so there is no file to point the login entry at. The toggle is held at whatever the entry says and the row explains, in the amber the settings pages already use for a held control. An entry written by an earlier installed run is left alone.
