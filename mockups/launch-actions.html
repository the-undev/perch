Launch actions: added from a shelf

The round answers: launch commands are a fixed five-slot table of raw TOML lines, written for one machine. After this round an action is something you add. The shelf offers presets (VS Code, the zellij tab, nvim, the folder, Obsidian, a custom command); picking one drops a card already filled in, and most adds never touch the command text. Each card is one [[launch.actions]] table; page order is the order on the bird.

Round of 1 November 2026 · drawn on the approved ink palette · verdicts to be recorded

An action is added, never assumed

A fresh config offers nothing on any bird. Each added action is one card and one config table, removed by removing the card. There is no fixed set of slots to leave empty.

A preset is starting text

Adding VS Code fills the card with ["code", "{path}"]; adding nvim fills in a terminal running nvim. The preset is not a live coupling: a machine with kitty instead of alacritty edits one field and the preset is never consulted again.

Two kinds only

Nearly every action is a verb and a command run detached, no shell, placeholders filled. The zellij tab keeps its find-or-open behaviour and carries its session fields. Obsidian becomes a plain command using {vault}, which also marks it as for vaults.

The card's head

Preset name, then the verb as the bird will say it, greyed. The arrows are the order on the bird; there is no separate ordering control to find.

Two fields, usually zero edits

Action is the words on the bird's page. Command keeps the config file's own list form, because a filled preset makes it text you read rather than text you write.

zellij's card

The one card with more on it: its two commands, the session default, and the roots. The shelf offers it once; a second tab action would be the same action twice.

3 · What saving writes

One table per card, in page order, under one namespace. kind is absent for a plain command. The [launch] table and its five named slots go; nothing else in config changes.

# ~/.config/perch/config.toml · written by Save, read back on change
[[launch.actions]]
kind = "zellij"
verb = "Open the zellij tab"
zellij = ["zellij"]
terminal = ["alacritty", "--working-directory", "{cwd}", "-e", "zellij", "attach", "-c", "{session}"]
session = "main"
[launch.actions.sessions]
"~/work" = "work"

[[launch.actions]]
verb = "Open in VS Code"
command = ["code", "{path}"]

[[launch.actions]]
verb = "Open in nvim"
command = ["alacritty", "--working-directory", "{path}", "-e", "nvim", "."]

[[launch.actions]]
verb = "Open the folder"
command = ["xdg-open", "{path}"]

A blank verb

6 · Widths

Small monitor (often primary)

Below about 900px the rail folds into a row of words above the column, as the settings page already does. Card heads drop the greyed verb before they truncate the name; the tools stay.

Desktop

Rail 168px, column up to 760px. Command fields take the full column; the two-up rows are for the zellij card's short fields only.

Ultrawide (3440px)

The shell caps near 1400px and centres. Nothing stretches; the shelf and the cards keep the column's reading width.

7 · What this round needs decided

The config shape breaks cleanly

[launch.commands] and its five named slots become ordered [[launch.actions]] tables, one per card, no legacy reader. One machine edits one file once; a config that no longer parses leaves the old one in force and says so in the sky.

{vault} is the vault marker

An action whose command uses {vault} is offered on vault birds only; everything else goes to any bird with a folder. The alternative is a separate scope field, a second way of saying what the command already says.
