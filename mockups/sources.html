Sources: perch starts from nothing

The round answers: the starter config mirrors the owner's real setup, and the UI assumes Forgejo and every source exists. After this round perch assumes nothing. A fresh start holds no places to look; sources are added one at a time, each explaining itself, and new kinds of source slot in without redesign.

Round of 23 October 2026 · drawn on the approved ink palette · verdicts to be recorded

A source is added, never assumed

No source is present until the owner adds it. An absent source gathers nothing, judges nothing, and leaves no trace in the UI: no empty Forgejo panel, no unmet expectation.

Each source carries its own truth

A source card shows what its last scan found, in words: read 18 repositories, failed with the reason, or never scanned. Status lives with the thing configured, not in a far-off log.

The list is a registry

The picker renders whatever kinds core registers: name, one plain sentence, what it needs. A future source (tickets, a reading list, a phone) is one more row, not a new screen.

The button no longer writes a copy of anyone's setup. It creates a config holding only defaults (one wire, the standard thresholds) and goes straight to Sources. The owner's own places are typed by the owner.

Status with the thing

The collapsed card's right edge is the last scan's verdict in words. A failure names its reason where you would fix it; the sky's notices stay for passing weather.

The token field

Write-only. Pasting and storing puts it in the keyring under the key shown; the field then shows only dots that cannot be revealed. The keyring key is suggested from the account name and stays editable.

Test before trusting

Test reads the account's repository count with the stored token and says so in a sentence. A failure says what the forge answered.

Multiples

Every kind can be added any number of times: one card per connection, each with its own token, test and verdict. Two GitHub accounts are two cards; a second Forgejo server is a third. The picker always offers every kind.

6 · What this round needs decided

Config grows a sources shape

Every source becomes optional, repeatable and lives under one namespace, as array tables: [[sources.local]], [[sources.github]], [[sources.forgejo]], [[sources.kuma]]. One table per card; none, no source. The old [local]/[forges]/[server] shape goes; nothing real uses it yet, so there is no migration to carry.

one breaking rename now, while the only config in the world is a starter.

The starter is generated, not copied

"Create the config file" writes writeConfig of a default config: one wire ("Projects"), standard thresholds, no sources. The repo's example file becomes a commented reference with placeholder values only; no real accounts, addresses or key names anywhere in the repository.

generate the starter; keep the example as documentation with fake values.

perch may store tokens into the keyring

The paste-once field writes through the Secret Service API under service perch. perch still never reads a token back for display and nothing touches disk; the existing rule holds. The manual command remains printed beside it.

yes; it is the single biggest help to starting from nothing.

Claude Code sessions stay automatic

Session recency rides along wherever local folders are configured, costing nothing to set up. The registry leaves room for it to become a visible source row later.

leave it automatic this round.
