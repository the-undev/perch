The fixed stage

A desktop app is an instrument panel, not a document. The window never scrolls: the strip, the heading and the bird are furniture, bolted down, and each pane beneath moves only its own contents. This round resolves the roadmap's "Elements scroll, not the page", and it is the floor the papers and the camera's pan both stand on.

1 · The stage, live

Everything above the ground line is fixed: the strip, the heading with its actions, the bird on its roost. Below it, the record pane and the paper pane each scroll on their own; scroll one and the other holds still, and the wheel moves whichever pane is under the pointer, never the window. Scrollbars are thin and quiet, the desktop grain. Try both panes, then press The papers: the sheet rises over a stage that cannot move, so nothing can jump. Width toggles between the two monitors.

Skiff

Skiff guards your personal media collection: a local-first media manager and gallery for images, GIFs, and videos. Media lives as real files on disk, organised into collections. Skiff indexes and surfaces it, and never moves or owns it.

Stack

  • Backend: C# / .NET 10, ASP.NET Core minimal APIs, EF Core + SQLite
  • Frontend: React, TypeScript, Vite, Tailwind CSS v4

Prerequisites

  • .NET SDK 10
  • Node.js ≥ 24 and pnpm
  • ffmpeg on PATH

Running

dotnet run --project src/Skiff.Server starts the API, pnpm dev the gallery. The extension builds with pnpm --filter extension build.

Collections

A collection is a folder the indexer watches. Ratings, likes and covers are sidecar data; the files themselves are never written. Disliked items hide by default, and All is the explicit override.

The extension

The browser extension captures media from the page under review, resolves quality against site patterns, and queues it for ingest. Stages 1 to 4 are built; ingest, the server's write door, is designed next.

Licence

AGPL-3.0-or-later. Early development; breaking changes land often.

2 · The narrow window

Below one threshold the two panes cannot sit side by side. The record pane takes the ground alone, and the key files join the record pane's flow as the last section, scrolling with it, exactly as the page stacks today. One pane, one scrollbar, no nesting: the fixed stage holds, only the number of panes changes. Toggle "narrow window" above to see it. The alternative, folder tabs over one pane switching between record and files, is sketched in the verdicts as the option it is.

3 · What this buys

The wheel always answers the pane under the pointer, so a long README and a long ledger stop fighting. The key-file paper loses its height cap and its nested scrollbar: it fills its pane. The papers rise over panes that cannot move, which ends the scroll-jump class of bug outright. And the camera's pan (phase 5) gets its stage for free: a fixed strip over a ground that pans, nothing else moving.

  • The window never scrolls. The strip, the heading, the actions and the roost are fixed furniture; only panes move their contents.
  • Two panes on the ground: the record (ledger, branches, river, pull requests) and the paper (key files), each with its own quiet thin scrollbar.
  • Narrow windows go to one pane, the key files joining the record's flow at the end, as the page stacks today. (Alternative: folder tabs switching one pane between record and files; pick on feel.)
  • The papers rise over the still stage, panes dimmed and inert beneath, the sheet as built on the branch; a proper modal stays the fallback if the risen sheet still reads wrong here.
  • Out of this round: the aviary and settings pages already fit or scroll their own rails; they adopt the same rule later if ever needed.
